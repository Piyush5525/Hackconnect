# Known issues and deferred work

Explicit scope gaps against the build brief. Nothing here is hidden behind placeholder logic: unimplemented features either return a clear error (`503 ... not configured`) or are simply absent.

## Not built
1. **Identity:** email+password (with email confirmation, password reset and account lockout), Google and GitHub sign-in/linking. Google/GitHub are tested against a fake provider, **not yet against the real services** (needs your client IDs). Email delivery over SMTP is tested against a fake server; STARTTLS upgrade is implemented but not exercised against a real TLS server. Missing: magic link, 2FA, device/session list, profile fields (bio, skills, timezone, links), team finder, join requests, invite-by-email/username.
2. **Storage and scale:** all state is one JSON file in one process (atomic writes, **automatic backups every 15 min with recovery from the newest good backup if the file is damaged**). No PostgreSQL, Redis, S3 or migrations; no horizontal scaling; the IP rate limiter is per-process. Fine for one hackathon on one VM; not for multi-tenant SaaS. No point-in-time recovery.
3. **Editor:** Monaco bound to Yjs with tabs, nested file tree, rename/delete/new folder, drag-drop import, status bar and themes. Still missing: per-user undo (undo is local to the model), full TypeScript project intelligence (semantic checks are off), LSP, inline comments, binary/image files (only text files are stored), and VS Code Marketplace extensions (they need VS Code itself; use the downloadable HackConnect VS Code extension instead).
4. **Terminal and previews:** no PTY, no shared-terminal modes, no port detection, no idle shutdown. Tunnel previews go through a signed, sandboxed, read-only proxy (no WebSockets/HMR, absolute-path apps break). A one-shot `POST /run` exists behind `HACKCONNECT_RUNNER=docker` (hardened argv unit-tested); **it has never been run against a real Docker/gVisor host here**: run `npm run verify:runner` on the target machine, which checks network, filesystem, user, capabilities, limits and timeout, before enabling it. Judge "Run in sandbox" and "Full VS Code" mode are not built.
5. **Media:** only browser-to-browser WebRTC (public STUN, no TURN) and a screen-share button. LiveKit token endpoint exists but the UI does not use it. No push-to-talk, device picker, noise suppression, event/breakout rooms, raise-hand, judge Q&A room or recording.
6. **Chat:** per-workspace persisted text only. No markdown, uploads, reactions, mentions, unread counts, search, DMs, or team/event channels.
7. **Local Bridge:** `login`, `workspaces`, `share`, `expose`, `status`, `logout` work (tested with a real subprocess on Windows). Missing: `terminal` mirroring; automatic agent detection (use `--agent <name>` to tag a session); single-file binaries and npm publication; testing on macOS/Linux (Linux needs Node 20+ for recursive watch). `expose` registers a `cloudflared` URL but there is no authenticating proxy, so the unguessable URL is the only barrier.
8. **Agents:** each user can save their own provider, model and encrypted API key (Ollama, Groq, Gemini, OpenRouter, OpenAI, Claude, any OpenAI-compatible server) and connect external agents over MCP. The assistant is request/response (no streaming), keeps a short per-project history in the browser, and sends at most ~60 KB of project files as context. No ACP, org-level keys or usage quotas. The user-supplied endpoint check resolves DNS before connecting but does not pin the resolved IP, so a DNS-rebinding attacker on a hosted server could still reach private addresses; run hosted installs with `HACKCONNECT_ALLOW_PRIVATE_AI=false` and network egress rules.
9. **GitHub:** one-way file upload using the signed-in user's own connected GitHub account (Connections > Connect GitHub); there is no server-wide GitHub token. No GitHub App, import, branches, PRs, webhooks, conflict UI, or git remote for the workspace.
10. **Events:** no custom registration questions, approval/waitlist, sponsors/FAQs/prizes/banner, starter repos or templates, or event-wide voice rooms. The `deadline` is enforced automatically (warning 15 minutes before, then workspaces freeze and judging starts; checked every 30 s) but there is no UI to set it yet other than `PATCH /api/events/:id {deadline}`. Mentor queue and broadcast are API/dashboard-count level.
11. **Judging:** single round only; recusal is limited to "you are on the team"; "first working version" signal needs the runner so it is `null`; results page and gallery are minimal; several organizer/participant forms use browser `prompt()` dialogs.
12. **Platform:** no email or web-push notifications (in-app only), no Stripe interface (quotas and plans are enforced, billing is not), feature flags are stored but only the kill switch is enforced, no i18n, no formal accessibility audit, no command palette, onboarding checklist or light theme.
13. **Frontend:** the supplied HTML/JS design was kept (not migrated to a framework); its script was moved out of `index.html` so the CSP forbids inline scripts. Inline styles remain.
14. **Quality tooling:** coverage is not measured; no OpenAPI document (see `docs/API.md`); the CI workflows in `.github/` have **not run on GitHub** (no remote here) but a test validates their YAML, action refs, npm scripts, Dockerfile COPY sources and compose/Caddy consistency; no combined `e2e/acceptance.spec.ts` (two focused Playwright scripts cover editor sync and the event lifecycle); the sandbox, LiveKit and Caddy compose files are unverified on real hosts.

## Behaviours to know about
- The first account to sign up becomes platform admin. A new installation starts empty (no demo projects or accounts); projects left over from the old demo seed are removed on start.
- Workspace history for replay is recorded on each save/persist (about every 0.5 s of typing), not per keystroke. It is stored as compact patches with periodic checkpoints and keeps the latest 20,000 saves per workspace.
- Event status is forward-only. Re-freeze/unfreeze are separate organizer actions.
- Process signals (balance, agent share, paste markers) are informational and never change scores.

15. **Import limits:** text files only, 500 KB each, 3,000 files / 50 MB per workspace, 300 files per upload request; GitHub import takes the first 400 text files of a repository and is rate limited by GitHub (connect GitHub in Connections for a higher limit and private repositories).
16. **Project page:** contributors are derived from the edit history (one entry per save), so imports and many small saves count as edits, not lines; language percentages count programming and markup languages by bytes and ignore Markdown, JSON, YAML and plain text, like GitHub.
